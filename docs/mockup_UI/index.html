MOPAY UI concepts conceptual work · no application code changed

Four directions for the MOPAY interface

Each concept is a complete UI direction – layout, navigation, components, density, colour and interaction – based on .ai/UI_DESIGN_GUIDELINES.md. All current features are kept; improvements that go beyond styling are marked Better inside each mockup. Synthetic demo data only. Every page has light and dark themes and several clickable screens.

Final direction

Ledger – final

Concept A as the base, with Overview as the start page (former Reports), the cell inspector from C as an overlay drawer (Value → Entry details → Tag → Entry), Savings and Settings page from D, and the mobile layout from B.

Explored concepts

Concept A

Ledger

Evolution of today's UI into a classic application shell: sidebar, compact header, spreadsheet-grade grid.

  • Sticky header, name column and totals
  • Keyboard cell navigation
  • Entry drawer, mode banners, bulk bar
 Concept B

Monthly

Top navigation and a month-first workflow for the recurring task: enter this month, check the balance.

  • Month view with previous month and change
  • Fill empty values from last month
  • Mobile list + bottom sheet editor
 Concept C

Inspector

Dark-first three-pane workspace for power users: rail, dense grid, persistent inspector, command palette.

  • No Tags/Remove/Arrange modes on desktop
  • Ctrl/⌘ K for every action
  • Reports with one combined chart
 Concept D

Calm home

Warm, readable, overview-first interface for every household member; settings become a page.

  • Overview replaces Reports as home
  • Notes from tags in one list
  • Savings list + detail with quick contribution

Recommendation

Use A as the base – it follows guideline §29 (extend, don't replace), keeps spatial memory and has the lowest risk. Then add, in this order: B's month view as a second view of Expenses/Incomes (biggest workflow gain, and it solves mobile), D's settings page and notes from tags, and later C's command palette as an optional shortcut layer.
