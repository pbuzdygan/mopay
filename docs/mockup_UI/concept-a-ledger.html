MExpenses

Expenses – what changes and why

  • Stable application shell (§34, §37): primary navigation, working year and data operations move to a sidebar. The year is global context, so it sits above the sections it affects instead of beside search.
  • Compact page header (§36): title + count, one primary action (New entry split button with New group), secondary Edit menu holding Arrange / Remove / Tags. Same functions as today's New ▾ and Actions ▾.
  • Summary strip instead of nothing: year total, monthly average, current month vs average, highest month. Numbers only – no decorative cards (§21).
  • Grid built for scanning (§13): real <table>, sticky header, sticky name column and sticky totals row; groups become subtle section rows with inline subtotals instead of saturated purple bars, so colour is left for meaning.
  • Tags render as a thin coloured bar inside the cell plus a corner mark when a note exists – visible without hiding the number.
  • BetterKeyboard editing: arrows/Tab move the cell cursor, Enter or typing starts editing, Esc cancels – spreadsheet behaviour on top of the existing per-cell PATCH.
  • BetterGroup subtotals are always visible in the group row; the Show group totals setting can remain as an opt-out.

Entry drawer

  • Replaces the centred context panel with a right-side drawer (§39 list → drawer). The table stays visible for orientation.
  • Same fields as today (name, group, comment, remove) plus read-only insight: sum, average, highest month and a 12-month bar strip computed client-side from data already loaded.
  • Destructive action sits in a separated area with explicit label Remove entry and a confirmation step (§12, §20).

Tag mode

  • A mode banner states which mode is active and how to leave it (§11 "where am I"). Today's state is only visible in the button label.
  • Popover keeps today's tag model (none / grey / green / orange / red + note) with labelled colour swatches and explicit Save tag / Clear tag.

Remove mode

  • Checkbox column appears in place; groups can be selected as a whole. Selected rows are tinted red.
  • A floating bulk bar shows the selection count and the destructive action with a specific label (Remove 2 entries) – fulfils §9 action labels.
  • Arrange mode uses the same pattern with drag handles in the same column.

Savings

  • Goals become rows of one list (no card-per-goal) with aligned columns: name, balance / target, progress, percentage, menu (§7).
  • Edit / delete move to a row menu; item rows show actions on hover only, removing 2 icon buttons per row (§13).
  • Temporary withdrawals keep their caption as a warning badge; goals without target show "No target" instead of a progress bar.

Year operations

  • Two clearly separated tasks: Create year and Delete years. Years are a checklist with entry counts so the user knows what is lost.
  • BetterDeletion requires typing the year (or "DELETE" for several) – matches the irreversibility of the action. The working year cannot be the last remaining year (existing rule, now explained inline).
  • BetterOptional "Copy entries and groups from 2026" when creating a year – structure only, values empty. Frontend can do this with existing endpoints; flag as optional.
